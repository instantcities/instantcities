# Developer guide

How the project is put together and how to work on it. For what the game is, see the [README](../README.md).

## Running it

```bash
python3 serve.py                              # only the games: http://localhost:8321/ghent/play/
bundle install && bundle exec jekyll serve    # the whole site: http://localhost:4000/
```

The game uses ES modules, so it needs a local server. Three.js and the fonts load from CDNs, so you
also need an internet connection. GitHub Pages builds the Jekyll site on every push, and every pull
request gets a Netlify preview (`netlify.toml`). With Ruby 4, the old Liquid that GitHub Pages pins
needs `RUBYOPT=-r<file defining Object#tainted? as false>`; Ruby 3 works as is.

## Layout

```
core/            the game, the same for every city
  js/            the engine: riders, tracks, scenery, quests, sound
  js/game/       the game itself, one file per part (menu, race, touring, hud, minimap, ...)
  js/inside/     what building interiors are made of
  sounds/, style.css, game.html (template for each city's play page)
ghent/, lecce/   a city with everything about it
  index.html     its page on the site (only `layout: city`; the words are in _data/cities.yml)
  play/          the game page, generated by tools/pages.mjs, don't edit by hand
  city.js        the map, routes, quests, sights and look (see the header of the file)
  page.json      the title, colours and share text of the game page
rome/, paris/    smaller cities: a first map, a race and a tour (docs/first-maps.md)
cities/          the cities page
tools/           scripts that make the maps and pages (not part of the site)
_data/, _layouts/, _includes/   the Jekyll site
```

Every city has two addresses: its page at `/<id>/` and its game at `/<id>/play/`. The engine reads the
city from `core/js/city.js`, which takes it from the bare name `city`; each city's page maps that name
to its own `city.js` in an import map.

## Adding a city

1. Make a folder with an `area.json` (input for `tools/osm_map.mjs`), a `city.js`, a `page.json` and a
   `loader.html` (the scene on the loading screen).
2. Run `node tools/pages.mjs` to make the game pages.
3. For the site, add a block to `_data/cities.yml` and an `<id>/index.html` with `layout: city` and
   `city: <id>`.

The id is also the address, so it can't be `core`, `assets`, `cities`, `docs` or `tools`.
More in `docs/new-maps.md` and `docs/first-maps.md`.

## Building a map

```bash
node tools/osm_map.mjs ghent --fetch   # download the area (cached in tools/cache/) and build ghent/map.js
node tools/osm_map.mjs ghent           # rebuild from the cached download
```

`area.json` holds the town, the bounding box, the corners of the zone to keep and the routes (an id
and street names in riding order). A route with `from` and/or `to` ([lat, lon]) is an open route,
ridden once from a start gate to a finish gate. If a route won't build,
`node tools/routecheck.mjs <city> --route <id>` shows which streets meet and which are in separate pieces.
A new route also goes in the city's `races.js`.

Other map tools:

- `tools/gent3d.mjs` takes a few Ghent landmarks from Stad Gent's "Gent in 3D" models (needs `dwg2dxf`). Run it again after rebuilding the map.
- `tools/terrain.mjs ghent` makes the hill by the Blandijn from Digitaal Vlaanderen's terrain model. A city without a `terrain.js` is flat.
- `tools/photos.mjs` and `tools/street.mjs` fetch photos (Wikimedia Commons, Mapillary) to draw house fronts from. Mapillary needs a token in `MAPILLARY_TOKEN`.
- `tools/facadinator.mjs` colours a street's fronts from those photos. See the `facadinator` skill.

Buildings are drawn in three levels: landmarks by hand (`landmarks.json`, `facades.js`), important
streets front by front from photos (`fronts.js`), and everything else from the OSM outline and height.

## Buildings you can enter

A city lists them in `<city>/inside.js` (the rooms, size, door, cards and light) and builds the rooms
in `<city>/inside/`. Each building stands on the city's map in a row 2 km to the east, so going in
is a teleport and nothing has to load. The shared parts are in `core/js/inside/`. Use
`/<city>/play/?inside=<id>` to go straight in.

## Site content

Landmark pages, art pages and city guides are generated from data files:

| Content | Data | Command |
|---|---|---|
| Landmarks (`/<id>/landmark/<name>/`) | `_data/landmarks/<id>.json` | `node tools/landmarks.mjs` |
| Art (`/art/`) | `_data/art.json` | `node tools/art.mjs` (`photos` fetches pictures from Wikimedia Commons) |
| City guides (`/<id>/about-the-city/`, `/<id>/places-and-landmarks/`) | `_data/about/<id>.json` | `node tools/about.mjs` |
| Map of Europe | `_data/europe.json` | `node tools/europe.mjs` |

Photos must be freely licensed (CC BY, CC BY-SA, CC0 or public domain) and credited on their page.
A museum in `art.json` whose `landmark` is a landmark id gets linked both ways with that landmark's page.

## Website preview videos

The home page plays 18-second silent videos of a few cities. Each city's `<city>/website-preview.json`
lists three six-second shots. To rebuild them (needs Chrome, `playwright` and `ffmpeg`):

```bash
node tools/website-preview.mjs          # all of them
node tools/website-preview.mjs paris    # one city
```

The videos go in `assets/previews/` and are committed. Rebuild a city's video when its map or tour changes.
The order is `preview_cities` in `_data/home.yml`.
